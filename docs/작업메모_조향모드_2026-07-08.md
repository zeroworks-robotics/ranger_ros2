## 2. combined 명령 버그 (0fab72b)

### 증상
- teleop로 linear+angular 동시 입력 시 **직진 성분이 사라짐**. 조이스틱은 정상.

### 원인
`TwistCmdCallback`에서 회전반경 `radius = |linear.x| / |angular.z|` 가 `min_turn_radius`보다 작으면 무조건 **SPINNING 모드**로 전환 → SPINNING 분기는 `SetMotionCommand(0, 0, angular)`로 **linear을 버림**.
- teleop 기본값(0.5 m/s + 1.0 rad/s = 반경 0.5 m)은 Ranger `min_turn_radius`(0.81) 미만 → 항상 스핀.
- 조이스틱은 아날로그라 반경이 커서 DUAL_ACKERMAN 유지 → 정상.

### 수정
스핀 조건을 변경:
```
before: radius < min_turn_radius            → SPINNING
after : |linear.x| < 1e-6 && |angular.z|>0  → SPINNING (순수 제자리회전만)
        그 외                                → DUAL_ACKERMAN (조향각 최대 클램프 → arc)
```

### teleop 사용 시 주의 (버그 아님)
- 터미널은 한 번에 한 키만 읽어 각 키가 twist를 **덮어씀**. `i` 후 `l`은 동시가 아니라 교체.
- **동시 명령은 대각선 키 `u` `o` `m` `.` 로만** 나옴 (linear+angular 한 메시지에 함께).

## 3. 조향 모드 steer_mode (495f588)

`steer_mode` 파라미터 추가. 기본 `twist`라 기존 동작 불변.

| | **twist** (기본) | **direct** |
|---|---|---|
| `angular.z` 의미 | 각속도(yaw rate, rad/s) | 조향각(rad) 직접 |
| 조향각 결정 | linear/angular 비율로 **계산** | angular.z **그대로** (max 클램프) |
| 속도 영향 | 있음 (빠르면 완만, 느리면 급) | **없음** (속도 무관, 핸들 각 고정) |
| `j`/`l` (회전만) | 제자리 회전(SPINNING) | 바퀴만 꺾이고 안 움직임 |
| 용도 | **자율주행/알고리즘**(nav2 등) | **조이스틱/수동 조종** (RC 느낌) |

### 숫자 예시 (angular.z=0.5 고정)
- twist: 0.5 m/s → 조향 ≈24°, 1.0 m/s → ≈13° (속도 따라 자동 조절, 원 궤적 유지)
- direct: 0.5 m/s → 28.6°, 1.0 m/s → 28.6° (동일, RC 핸들과 같음)

### 구현 위치
- `ranger_messenger.hpp`: `bool direct_steer_` 멤버
- `ranger_messenger.cpp` `LoadParameters`: `steer_mode` 파라미터 선언 → `direct_steer_` 설정
- `TwistCmdCallback`: `else if (direct_steer_)` 분기에서 `steer_cmd = angular.z`, DUAL_ACKERMAN 유지
- 조향각 클램프·`SetMotionCommand(linear.x, steer_cmd)`는 기존 DUAL_ACKERMAN switch 재사용
- bringup 런치 4종에 `steer_mode` 인자 배선

## ⚠️ direct 모드 주의사항

1. **자율주행(nav2 등)과 호환 안 됨** — 가장 중요.
   `angular.z`를 조향각으로 해석하므로 yaw rate를 보내는 알고리즘/nav2와 함께 쓰면 오동작. **자율주행은 반드시 `twist`.**
2. **제자리 회전 불가.**
   `j`/`l`(linear.x=0, angular만) → 바퀴만 꺾이고 안 움직임(자동차 중립+핸들만). 제자리 회전 필요 시 `twist`.
3. **조향각 상한 0.698 rad(40°), 초과분 클램프.**
   teleop 기본 turn=1.0은 상한 초과라 항상 풀락. 중간 각도는 `turn ≈ 0.5`로 설정
   (`ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p turn:=0.5`).
4. **조이스틱은 angular 스케일 조정 필요.**
   `teleop_twist_joy`의 `scale_angular ≈ 0.7`로 맞춰야 스틱 편향이 조향각에 비례. 스케일이 크면 살짝만 밀어도 풀락.
5. **속도 무관 = 고속에서 더 공격적.**
   같은 조향각을 유지하므로 빠를수록 실제 선회(yaw rate)가 커짐. 고속 급조향 주의. (twist는 반대로 자동 완만해짐)
6. **기본값은 twist라 옵트인.**
   `steer_mode:=direct` 명시할 때만 적용. 안 붙이면 기존 twist 동작 그대로.

## 4. 사용법

```bash
# 자율주행/알고리즘 (기본)
ros2 launch ranger_bringup ranger.launch.py

# 조이스틱/수동 (RC식 직접 조향)
ros2 launch ranger_bringup ranger.launch.py steer_mode:=direct
```

### direct 모드 조향각 세팅
- `angular.z` 값 = 조향각(rad). 유효 상한 = `max_steer_angle_ackermann` = **0.698 rad (40°)**, 초과분은 클램프.
- teleop_twist_keyboard turn 값 권장: **0.5** (≈29°, 상한 여유). 최대 선회는 0.7.
  ```bash
  ros2 run teleop_twist_keyboard teleop_twist_keyboard --ros-args -p turn:=0.5
  ```
- 조이스틱(`teleop_twist_joy`)이면 `scale_angular ≈ 0.7`로 두면 스틱 끝 = 최대 조향으로 비례.

| turn(angular.z) | 조향각 |
|---|---|
| 0.7 | 40° (풀락) |
| 0.5 | ~29° |
| 0.35 | ~20° |
| 0.17 | ~10° |

## 5. 검증 상태

- `colcon build` (ROS 2 Humble, docker 컨테이너 `cona_icn_ros2`) **통과** — 수정 소스 경고 없음
- 런치 4종 Python 구문 검사 통과
- **실기 검증 완료**:
  - twist: `u`/`o` combined → `motion_mode=0`(DUAL_ACKERMAN), 호 주행 / `j`/`l` → 제자리 회전
  - direct: `u`/`o` → 조향각 직접 반영된 호 주행

### 판별 팁
combined 명령 중 `ros2 topic echo /motion_state` 의 `motion_mode`:
- `0` = DUAL_ACKERMAN (정상, 호 주행)
- `2` = SPINNING (구버전 바이너리 or linear 없이 회전만)
