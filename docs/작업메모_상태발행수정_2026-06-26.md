## 핵심 디테일 (왜 이렇게 고쳤나)

### C1 — 8 actuator = 4륜 × (구동 + 조향)
- ugv_sdk `RangerActuatorState`는 `actuator_hs_state[8]`, `actuator_ls_state[8]` 배열 + `motor_angles(angle_5~8)` + `motor_speeds(speed_1~4)` 구조.
- 기존 코드는 `actuator_ls_state->`(= `[0]`)만 읽어 **나머지 7개 모터 데이터 전부 유실**.
- 네이밍이 매핑의 결정적 단서:
  - `speed_1~4` → 구동모터 = actuator **id 0~3**
  - `angle_5~8` → 조향모터 = actuator **id 4~7**
- SDK 파서(`can_id - ACTUATOR1_ID`로 0~7 인덱싱)와 데모(`ranger_robot_demo.cpp`)로 교차 확인.

### H1 — robot_model 미전달이 더 심각했음
- 원래 `update_rate`만 누락인 줄 알았으나, `ranger_mini_v1/v2` 런치는 **`robot_model`도 dict에 없어** 노드가 기본값 `"ranger"`로 동작 → 잘못된 휠베이스/트랙/속도 파라미터 로드.
- 4개 런치 파일 모두 `update_rate` + `robot_model` 배선으로 통일.

### M3 — 동작은 그대로
- `40.0 * M_PI / 180.0` = 0.6981 rad = `max_steer_angle_ackermann`(전 모델 동일) → 숫자상 동일, 매직넘버만 제거.
- 미사용 변수 `x`, `w`와 주석 처리된 식 제거.
